# Nitro Self — سایت + ربات تلگرام (نسخه پایه قابل استقرار)

این پروژه شامل سایت فارسی RTL با ظاهر سرمه‌ای/طلایی و یک ربات تلگرام واقعی برای منو، ثبت کاربران، نمایش موجودی، حساب کاربری و ابزارهای پایه ادمین است. سایت و ربات از یک دیتابیس مشترک استفاده می‌کنند.

## چه چیزهایی واقعاً کار می‌کند؟
- ربات تلگرام با `/start` و منوی فارسی
- دکمه باز کردن سایت به‌صورت Telegram Mini App (نیازمند دامنه HTTPS)
- ثبت کاربر در دیتابیس مشترک
- سایت با ورود امن Telegram Mini App و اعتبارسنجی `initData`
- نمایش موجودی، تاریخچه تراکنش‌ها و سلف‌های ثبت‌شده
- ثبت رکورد سلف در سایت (فقط رکورد دیتابیس؛ نه اجرای نشست سلف)
- ادمین: `/admin` و شارژ/کسر الماس با `/adddiamonds USER_ID AMOUNT NOTE`
- مسیر `/health` برای بررسی اتصال دیتابیس

## مواردی که هنوز فعال نیستند
این پروژه یک پایه واقعی برای سایت و ربات است، اما **هنوز ماژول اجرای سلف موجود شما، از جمله `helper_bot.py`، به آن متصل نشده است**. بنابراین دکمه مدیریت سلف نشست تلگرام را روشن نمی‌کند. خرید گیفت، فروشگاه، انتقال الماس، گردونه، چالش، لیدربورد و درگاه پرداخت نیز تا اتصال سرویس/قوانین واقعی غیرفعال یا نمایشی‌اند. برای اتصال سلف واقعی باید فایل‌های فعلی پروژه سلف‌ساز بررسی شوند؛ بدون آن‌ها نباید ادعای فعال‌سازی واقعی کرد.

## استقرار پیشنهادی در Railway
از **یک Railway Project** با سه سرویس استفاده کنید: سایت، ربات، PostgreSQL. اگر پروژه PostgreSQL دارید، از همان دیتابیس استفاده کنید.

### 1) آپلود پروژه به GitHub
1. ZIP را از حالت فشرده خارج کنید.
2. تمام فایل‌ها را به یک repository در GitHub آپلود کنید؛ فایل `.env` واقعی را آپلود نکنید.
3. فایل‌های لازم: `main.py`, `bot.py`, `templates/index.html`, `requirements.txt`, `Procfile`.

### 2) ساخت دیتابیس
1. در Railway وارد پروژه شوید.
2. `New` → `Database` → `PostgreSQL` را انتخاب کنید.
3. نام سرویس دیتابیس را به خاطر بسپارید، مثلاً `Postgres`.

### 3) سرویس سایت
1. `New` → `GitHub Repo` و مخزن بالا را انتخاب کنید.
2. نام سرویس را مثلاً `nitro-web` بگذارید.
3. در `Variables` مقدارهای زیر را اضافه کنید:
   - `BOT_TOKEN` = توکن ربات از BotFather
   - `BOT_USERNAME` = نام کاربری ربات بدون `@`
   - `ADMIN_IDS` = شناسه عددی ادمین؛ چند شناسه با کاما جدا شوند
   - `WEBAPP_URL` = دامنه HTTPS سرویس سایت، پس از ساخت دامنه
   - `DATABASE_URL` = Reference Variable دیتابیس، معمولاً `${{Postgres.DATABASE_URL}}`؛ اگر نام دیتابیس شما فرق دارد، نام واقعی را بگذارید
   - `SECRET_KEY` = یک مقدار تصادفی طولانی
   - `WEBAPP_AUTH_REQUIRED` = `true`
   - `SUPPORT_USERNAME` = نام کاربری پشتیبانی بدون `@` (اختیاری)
   - `CHANNEL_USERNAME` = نام کاربری کانال بدون `@` (اختیاری)
4. در Settings/Networking دامنه عمومی HTTPS بسازید.
5. آدرس دامنه را در `WEBAPP_URL` سرویس سایت و ربات وارد کنید.
6. Deploy را بررسی کنید و `https://YOUR-DOMAIN/health` را باز کنید؛ انتظار می‌رود `{"database":"connected","ok":true}` ببینید.

### 4) سرویس ربات (در همان Railway Project)
1. `New` → `GitHub Repo` را بزنید و **همان repository** را انتخاب کنید.
2. نام سرویس را `nitro-bot` بگذارید.
3. در Settings، Start Command را دقیقاً بگذارید:
   `python bot.py`
4. در Variables، همان مقادیر `BOT_TOKEN`, `BOT_USERNAME`, `ADMIN_IDS`, `DATABASE_URL`, `SECRET_KEY`, `WEBAPP_URL`, `SUPPORT_USERNAME`, `CHANNEL_USERNAME` را وارد کنید. مهم است که `DATABASE_URL` دقیقاً به همان PostgreSQL وصل شود.
5. Deploy کنید و Logs را ببینید. نباید پیام Conflict مربوط به polling تکراری دیده شود. **فقط یک سرویس ربات با این توکن روشن باشد**؛ اگر نسخه دیگری از همین ربات در Railway/Termux در حال polling است، آن را متوقف کنید.

### 5) تنظیمات BotFather
- با `/setdomain` دامنه سایت HTTPS را برای ربات تنظیم کنید، اگر برای Mini App در تنظیمات شما لازم است.
- در ربات `/start` بزنید و روی «باز کردن پنل Nitro Self» کلیک کنید. سایت را مستقیم در مرورگر باز نکنید؛ ورود امن از داخل Telegram Mini App انجام می‌شود.

## دستورات ادمین
- `/admin` — آمار پایه
- `/adddiamonds شناسه_کاربر مقدار توضیح` — شارژ یا کسر موجودی. مقدار منفی برای کسر است.
- کاربر باید دست‌کم یک بار `/start` را زده باشد تا در دیتابیس ثبت شود.

## اگر می‌خواهید با Termux پوش کنید
از داخل پوشه پروژه:
```bash
git init
git add .
git commit -m "Add Nitro Self website and Telegram bot"
git branch -M main
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```
اگر repository از قبل فایل دارد، اول آن را بررسی کنید و از روی فایل‌های قبلی کورکورانه overwrite نکنید.

## امنیت
- توکن ربات، رمز دیتابیس و `SECRET_KEY` را در GitHub نگذارید.
- اگر توکن قبلاً در کد یا مخزن عمومی منتشر شده، در BotFather آن را تعویض کنید.
- برای شارژ واقعی، تراکنش باید در دیتابیس ثبت شود؛ به پیام یا اسکرین‌شات پرداخت به‌تنهایی اعتماد نکنید.
- اجرای سلف واقعی نیازمند اتصال جداگانه به ماژول نشست موجود است. نشست/کد ورود تلگرام را داخل مرورگر یا صفحه وب دریافت نکنید.
